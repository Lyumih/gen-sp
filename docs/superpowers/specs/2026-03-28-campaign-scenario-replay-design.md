# Повторное прохождение сценариев кампании

**Дата:** 2026-03-28  
**Статус:** draft — к реализации  
**Связь:** дополняет [gen-game-design](./2026-03-28-gen-game-design.md) (цепочка боёв, §7). **Не** описывает арену / эндгейм (отдельная спека при необходимости).

## 1. Цель

После прохождения **всей** линейной цепочки `SCENARIOS` игрок снова может начинать бои по **любому** сценарию из списка, с тем же сохранением: мета (`worldPower`, карты, уровень героя, цель модификаций) продолжает жить **одним** сейвом и подчиняется тем же правилам боя, что и основная кампания.

## 2. Область и ограничения

- **В объёме:** доступ к повтору только когда кампания уже «закрыта»: `scenarioIndex >= SCENARIOS.length` (текущая модель после победы в последнем сценарии).
- **Вне объёма (v1):** выбор «уже пройденного» сценария при **незавершённой** цепочке (например, тренировка на первом уровне, пока не пройден третий). При необходимости — отдельное решение в следующей ревизии.
- **Арена:** не входит в этот документ.

## 3. Правила прогресса

### 3.1 Победа в повторном бою

- В кампанию переносятся итоги боя так же, как сейчас при победе: актуальные `worldPower`, карты из боя и т.д. (существующая логика `finalizeVictory` по мете).
- **`scenarioIndex` не увеличивать**, если к моменту победы кампания уже была завершена:  
  `scenarioIndex >= SCENARIOS.length` → после боя оставить прежнее значение (например, `3` при трёх сценариях).
- Если кампания **ещё** шла линейно (`scenarioIndex < SCENARIOS.length`), поведение без изменений: `scenarioIndex += 1`.

Итог — одна функция финала победы с условием:

```text
nextScenarioIndex =
  state.scenarioIndex >= SCENARIOS.length
    ? state.scenarioIndex
    : state.scenarioIndex + 1
```

(плюс перенос меты из боя, как сейчас).

### 3.2 Поражение, retry, выход из боя

- Те же анти-дюп правила, что и для обычной цепочки: снимок попытки `battleAttemptSnapshot`, `RETRY_CURRENT_BATTLE`, `ABANDON_BATTLE`.
- **Обязательное изменение данных:** при старте боя в снимок попытки нужно записывать **индекс сценария этого боя** в `SCENARIOS`, а не выводить его из `campaign.scenarioIndex` при retry.

**Проблема текущего кода:** при `scenarioIndex >= SCENARIOS.length` выражение `SCENARIOS[state.scenarioIndex]` даёт `undefined`, поэтому повтор без явного индекса ломает retry.

**Решение:** расширить `BattleAttemptSnapshot` полем, например `scenarioSlotIndex: number` (0…`SCENARIOS.length - 1`):

- Линейная кампания: при входе в бой `scenarioSlotIndex = state.scenarioIndex` (как сейчас по смыслу «текущий сценарий»).
- Повтор после финала: `scenarioSlotIndex =` индекс, выбранный игроком в UI.

`RETRY_CURRENT_BATTLE` и сборка боя при retry используют `SCENARIOS[snapshot.scenarioSlotIndex]`.

### 3.3 Старт боя

- Новое действие рана, например `START_REPLAY_BATTLE: { scenarioSlotIndex: number }`.
- Условия: `state.battle === null`, `state.scenarioIndex >= SCENARIOS.length`, индекс в допустимых пределах.
- Сборка `BattleState` — та же, что для линейного сценария (`battleStateFromScenario`), но с `SCENARIOS[scenarioSlotIndex]`.
- В снимок попытки писать тот же `scenarioSlotIndex`.

`START_OR_CONTINUE_BATTLE` для завершённой кампании по-прежнему **не** начинает бой (или остаётся no-op); вход только через явный выбор сценария / кнопку повтора.

## 4. UI (ориентир)

- На хабе при «все сценарии пройдены»: вместо одной неактивной кнопки — возможность выбрать сценарий (список, селект или кнопки по `scenario.id`) и запустить бой.
- В бою / при поражении — без отдельной ветки, если заголовок может показывать `id` сценария из `SCENARIOS[snapshot.scenarioSlotIndex]` (опционально).

## 5. Персистенция и миграция

- Расширение `BattleAttemptSnapshot` требует **миграции** загрузки: для старых JSON без поля, если есть активный бой и снимок, задать `scenarioSlotIndex` как `min(campaign.scenarioIndex, SCENARIOS.length - 1)` при `scenarioIndex < length`, иначе **0** или последний валидный индекс — зафиксировать в `migrate.ts` один вариант (редкий случай «бой в процессе при обновлении»).

При необходимости поднять `SAVE_VERSION` и ключ `STORAGE_KEY` по правилам проекта.

## 6. Тесты (минимум)

- Победа в повторе при `scenarioIndex === SCENARIOS.length`: мета обновилась, `scenarioIndex` не изменился.
- Поражение → retry: бой снова с тем же сценарием (тот же `scenarioSlotIndex`), не с `undefined`.
- Линейная кампания: поведение `scenarioIndex` и retry без регрессий (снимок содержит правильный `scenarioSlotIndex`).
