# Дизайн: использование карт в бою + `%%` (этап A)

**Дата:** 2026-03-28  
**Статус:** реализовано (ядро + UI v1, см. план `docs/superpowers/plans/2026-03-28-card-use-in-battle.md`)  
**Связь:** `docs/superpowers/specs/2026-03-28-gen-game-design.md` (§3–§4), текущий MVP в `src/game/**`

## 1. Цель

Замкнуть в игровом цикле правило **«использование карты»**: при применении умения/удара с карточки растёт `uses_count`, бросается `1…100`, при успехе — `global_level+1` (канон `rollCardLevelUp`). Урон (или иной числовой параметр первого релиза) может выводиться из строки токена `%%` через существующий `resolvePercentValue(level, token)`.

## 2. Объём v1 (YAGNI)

**Входит:**

- Одно новое действие рана (или боя), атомарное: «герой использует карту по врагу».
- Разрешено **только в ход героя**, бой `phase === 'ongoing'`, цель — живой враг, дистанция и тип атаки (ближняя / дальняя) проверяются **теми же правилами**, что и для обычной `attack` в `combat.ts` (манхэттен, `maxRange` для дальнего).
- После успешного применения — **тот же сдвиг очереди**, что и после обычной атаки (через существующий `applyAction` или общий хелпер).
- Шаблон карты (по `templateId`): минимум поля **вид атаки** (`melee` | `ranged`), для дальнего — `maxRange`, **базовый урон**: либо число, либо строка одного токена `%%` для `resolvePercentValue`.
- UI: на экране боя кнопка(и) «использовать карту» + выбор цели (клик по врагу уже есть в режимах атаки — можно переиспользовать: режим «карта X» вместо фиксированного урона).
- Юнит-тесты: чистая функция «урон по шаблону + уровень»; тест рана/боя: после использования вырос `uses_count`, при фиксированном RNG возможен ап уровня; неверный ход (не герой / не та фаза / неверная дистанция) — no-op или без изменения карты (зафиксировать один стиль, предпочтительно **без траты использования**).

**Не входит (позже):**

- Несколько карт с разными эффектами (лечение, баффы, AoE).
- Расход MP, кулдауны, ограничение «одна карта за ход» сверх уже существующего «одно действие за ход».
- Привязка модификаций к формуле урона (только `global_level` для `%%` в v1).

## 3. Уровень для `resolvePercentValue`

Для **этого же удара** число из токена считается по **`global_level` до применения `applyCardUse`** (уровень «на момент замаха»). Так проще тестировать и совпадает с интуицией «сначала параметр удара, потом прогресс карты».

## 4. Архитектура и поток данных

1. **Каталог шаблонов** (`templateId` → параметры атаки и опционально `damageToken: string`): новый модуль в `src/game/` (например `content/cardTemplates.ts`), без React.
2. **Действие:** расширить `RunAction` в `runReducer.ts`, например  
   `{ type: 'USE_CARD_ATTACK'; cardId: string; targetId: string; randomInt1to100: number }`.
3. **Обработчик:**
   - взять `battle`, проверить ход героя (`getCurrentActorId` из `battle/reducer.ts`);
   - найти карту в `battle.playerCards`, шаблон по `templateId`;
   - вычислить `damage`: если задан токен — `resolvePercentValue(level, token) ?? fallbackDefault`, иначе константа из шаблона;
   - проверить `canMeleeAttack` / `canRangedAttack` для пары герой–цель;
   - применить `applyCardUse` к копии карты, записать обновлённый массив `playerCards` в копию `BattleState`;
   - вызвать `applyAction` с обычным `attack` и вычисленным `damage` / `kind` / `maxRange`;
   - если `applyAction` отклонил действие — **не применять** `applyCardUse` (проверки дистанции до прогресса карты).
4. **Порядок проверок (обязательно):** сначала валидность хода и дистанции на **исходных** картах, затем прогресс карты, затем атака. Так не растёт `uses_count` при промахе по правилам боя.
5. **Победа / поражение:** без изменений — итоговое состояние как у обычной атаки; `playerCards` в победившем бою по-прежнему мержатся в кампанию в `finalizeVictory`.

## 5. UI

- `BattleScreen`: режим «карта» (пер-карта или одна стартовая `c1`): сообщения через `App.useApp()`.
- RNG: в v1 для UI достаточно `Math.floor(Math.random() * 100) + 1`; тесты ядра передают константу через действие.

## 6. Тестирование

| Уровень | Что проверяем |
|--------|----------------|
| Чистая функция | `damageFromCardTemplate(template, level)` или аналог |
| `runReducer` / интеграция | После `USE_CARD_ATTACK` с валидной целью — `uses_count` +1; при RNG успеха — `global_level` +1; при неверной дистанции — состояние карты без изменений |
| Регрессия | Существующие тесты боя и кампании не ломаются |

## 7. Риски и ограничения

- Дублирование логики «кто сейчас ходит» между UI и раном — минимизировать: UI только шлёт действие, вся валидация в ядре.
- Тип `applyCardUse` возвращает `leveledUp` — в `BattleState` хранить только поля `CardInstance`, без лишнего поля в типе.
