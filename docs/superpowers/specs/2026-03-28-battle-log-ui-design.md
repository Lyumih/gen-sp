# Дизайн: журнал боя, выход/новый бой, отображение врагов в клетках

**Дата:** 2026-03-28  
**Статус:** утверждено к реализации  
**Связь:** `docs/superpowers/specs/2026-03-28-gen-game-design.md`, `2026-03-28-card-use-in-battle-design.md`, код `src/features/battle/BattleScreen.tsx`, `src/game/battle/reducer.ts`, `src/game/campaign/runReducer.ts`

## 1. Цель

- Вести **журнал текущего боя** (только пока существует объект боя; не сохранять в `localStorage` отдельно от `BattleState`).
- Дать **«Выйти из боя»** с откатом меты к снимку начала попытки и возвратом в хаб (анти-эксплойт, как при сдаче).
- Убедиться, что **«Начать новый бой»** после поражения работает через существующий `RETRY_CURRENT_BATTLE` и подпись понятна игроку.
- Показывать в **клетке врага** уровень (`unitLevel`) и жизни (`hp` / `maxHp`).

## 2. Журнал боя

### 2.1 Данные

- Поле в `BattleState`, например `battleLog: readonly BattleLogEntry[]`, изначально `[]` при каждом создании боя (`battleStateFromScenario`, retry).
- Записи — **структурированный union** (вид события + полезная нагрузка); отображаемый текст строит одна функция форматирования (удобно тестировать и расширять).

### 2.2 Когда писать

Добавлять запись **только если** действие реально изменило состояние (как сейчас: no-op редьюсера — без записи):

- **move** — кто, откуда/куда (или координаты до/после).
- **attack** (ближний/дальний) — атакующий, цель, урон; при смерти цели — отметить (для связи с наградами в логе опционально).
- **Использование карты** (`USE_CARD_ATTACK`): одна запись об атаке картой (урон, цель, идентификация карты/шаблона по аналогии с остальным UI).
- **Повышение уровня карты** после использования: если `applyCardUse` вернул `leveledUp === true`, добавить запись с **выпавшим значением броска** `randomInt1to100` (1..100), уровнем до и после, идентификатором карты/шаблона. Текст в духе: уровень N → N+1; **выпало R из 100**. Априорный процент успеха в UI **не** выводить (решение заказчика).

### 2.3 Где писать

- Ходы и обычные атаки: в `applyAction` в `battle/reducer.ts` (или тонкий хелпер, вызываемый оттуда), чтобы и ходы врага (AI) попадали в лог автоматически.
- Карта + бросок уровня: в `tryUseCardAttack` после успешной цепочки; для `leveledUp` и `R` нужно **не отбрасывать** результат `applyCardUse`: сегодня `cardAfterUse` отрезает `leveledUp` — пробросить флаг (и при необходимости временно вызывать `applyCardUse` до финальной сборки `CardInstance` для состояния).

### 2.4 Награды за килл без RNG

Рост **модификации** за убийство (`applyModKillReward`) детерминирован; в журнал при желании — отдельная короткая строка **без** «из 100». В минимальном объёме можно ограничиться записью об атаке/смерти; расширение — по необходимости.

### 2.5 UI

- Блок «Журнал боя»: прокрутка (`maxHeight` + `overflow`), новые записи **снизу**, по возможности мягкий автоскролл к последней строке.
- Очистка: при `battle === null` журнала нет; при новом бое массив новый.

## 3. Выйти из боя

- Новое действие рана, например `ABANDON_BATTLE`.
- Условие: есть активный `state.battle` и есть `state.battleAttemptSnapshot` (если нет — no-op).
- Эффект: восстановить из снимка `worldPower`, `cards`, `playerUnitLevel`, `modKillTargetCardId`; выставить `battle: null`, `phase: 'hub'`, `battleAttemptSnapshot: null` (как после победы — без «висящей» попытки). `scenarioIndex` не менять.
- UI: кнопка на экране боя, подтверждение через `Modal.confirm` (Ant Design), текст предупреждает о потере прогресса боя и отсутствии наград за эту попытку.

## 4. Начать новый бой

- Только при **поражении** (как сейчас): одна кнопка, подпись **«Начать новый бой»** (или эквивалент), действие — `RETRY_CURRENT_BATTLE` без дублирования логики.
- Существующий `Alert` с «Повторить бой» привести к одной понятной формулировке.

## 5. Клетки врагов

- Вместо одной буквы `E` — отображение **уровня** и **HP** (`hp/maxHp` или две строки), читаемый мелкий шрифт.
- При нехватке места — увеличить размер клетки (например больше 36px) и/или уменьшить `fontSize`. Герой и стены — текущая семантика символов или согласованное мини-оформление.

## 6. Тестирование

| Уровень | Что проверяем |
|--------|----------------|
| `battle/reducer` | После валидного move/attack в логе появляется ожидаемая запись; no-op — длина лога не меняется |
| `runReducer` | `ABANDON_BATTLE` откатывает мету и обнуляет бой; `RETRY_CURRENT_BATTLE` даёт бой с пустым логом |
| Карта + RNG | При фиксированном `randomInt1to100` и условиях успеха `rollCardLevelUp` — в логе есть запись с этим R и фактом level up |
